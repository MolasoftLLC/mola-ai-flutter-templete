# App Store公開前の許可・プライバシー確認（2026-10-13）

## 今回の変更

- メニュー履歴の開閉状態（bool）と味タグのスクロール位置（double）のPageStorageキーを分離。
- 履歴が空の画面には履歴読み込みの赤いエラーバナーを出さず、読み込み成功時には古い履歴エラーを解除。
- カメラ・写真・位置情報の目的説明を具体化し、日本語・英語のInfoPlist.stringsをRunnerのリソースに登録。
- 位置情報の説明に、周辺店舗検索時に現在地を当社サーバーとGoogleへ送信することを明記。
- 不要なApple Musicの説明キーを削除。ラベルカメラはenableAudio: false。
- 外部AIへ送信する写真・読み取り文字・検索語・好みの情報と送信先（Google、OpenAI、Perplexity）を説明し、解析前に明示同意を取得。アカウント単位・端末単位で記憶。ラベル写真の公開同意とは別に扱う。
- 対象入口：ラベルスキャン、メニュー解析、名前のAI検索、従来の名前・写真解析、保存写真の再照合・再解析。
- 公開プライバシーポリシーへ、位置情報の利用・送信・店舗情報の保存と、許可拒否時の代替操作を追記。

## 位置情報の経路

| 項目 | コードで確認した動作 |
| --- | --- |
| 許可範囲 | NSLocationWhenInUseUsageDescription。常時取得のキー・バックグラウンドlocationモードは追加していない。geolocator_appleはBYPASS_PERMISSION_LOCATION_ALWAYS=1。 |
| 許可要求 | マップの現在地操作、場所選択画面の周辺検索。許可済みならマップ初期表示でも現在地を取得。 |
| 拒否時 | 現在地へ移動・周辺検索は停止し、店名検索・地図閲覧は利用可能。 |
| 周辺検索 | アプリからPOST /api/places/search/nearbyで緯度経度を送信し、サーバーからGoogle Placesへ送信。 |
| 名前検索 | 端末位置を取得できなくても店名のみで検索できる。取得済みの座標がある場合は検索範囲の補助に利用。 |
| 保存 | 利用者が選択した店舗の緯度経度・名称・識別子をユーザーの記録へ関連付ける。 |
| 公開 | マップの店舗・商品情報を公開する。端末の現在地そのものをユーザー間で共有する機能は確認していない。 |

位置情報は単なる端末内処理ではない。登録店舗の座標がユーザーの記録に結び付いて保存されるため、App Store Connectの位置情報申告は確認が必要。

## App Store Connectで照合する収集データ

ストアの現在の申告内容はブラウザ未ログインのため未確認。下表は実装から整理した確認対象であり、設定済みという意味ではない。

| データ | 根拠・確認事項 |
| --- | --- |
| 位置情報（正確な位置） | 選択した店舗の座標をユーザーの記録に関連付けて保存。現在地の周辺検索もサーバー・Googleへ送信。用途はApp Functionality。 |
| 位置情報（おおよその位置） | Google Mobile Adsの同梱プライバシーマニフェストにCoarseLocationあり。広告設定・Googleの開示と照合。 |
| メールアドレス、名前、ユーザーID | Firebase認証、アカウント・プロフィール・記録の所有者管理。 |
| 写真・動画、その他のユーザーコンテンツ | 選択・撮影画像、感想、メニュー履歴、味の好み。動画投稿機能を追加したという意味ではない。 |
| 検索履歴 | ラベル解析の入力・結果や検索処理の保存・ログの実態を申告と照合。 |
| 製品の操作、デバイスID、広告データ、診断 | アプリ内タップ解析とGoogle Maps・AdMob等のSDK。ユーザーへの関連付け・追跡の用途は各SDK設定と併せて確認。 |

ATTはmain.dartでリクエストしている。広告SDKに関するストアの「追跡」回答は、ATTダイアログの存在だけで決めず、実際の広告配信設定・SDKの申告と照合する。

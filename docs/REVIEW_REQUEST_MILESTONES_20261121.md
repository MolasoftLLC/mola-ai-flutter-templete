# 操作完了後のレビュー依頼

## 表示候補

個人記録の編集保存（詳細の編集シート／保存酒詳細）またはマップ未登録一覧からの場所登録が成功し、保存・同期・スタンプの画面が完了した後にOS標準レビューAPIを呼ぶ。自動解析による保存、初回起動、失敗、キャンセル、「覚えていない」では呼ばない。

同じ記録の編集と場所登録を重複して数えず、3つ以上の異なる酒記録／メニュー記録を2つ以上の日に保存し、最初の保存から24時間以上経過したことを条件にする。いいね数・個人評価の点数・好みの一致率・感情によってレビュー依頼の対象者を選ばない。満足度を質問して高評価だけストアへ送る分岐は追加しない。

完了後3秒の間にタッチ操作、別画面・ダイアログ、バックグラウンド移行、アカウント切替、キーボード表示や再保存があれば見送る。次の正常な保存完了時に再判定する。レビュー依頼自体が失敗しても保存操作へエラーを返さない。

## 頻度とデータ

アプリ側で90日以上の間隔、同じバージョンでは1回、直近365日で3回までに制限する。進捗はアカウント別、依頼履歴は端末全体で共有してアカウント切替による連続表示を防ぐ。記録IDとアカウントのキーはハッシュ化し、端末内SharedPreferencesだけへ保存する。感想・評価・場所・写真・生UIDを収集・送信しない。

OS呼び出し前に依頼履歴を保存して二重実行を防ぐ。OSが表示したか、レビューを書いたか、星を何個付けたかは分からないので「レビュー済み」とは記録しない。手動の「アプリを評価する」からストアを開いた場合も自動依頼の間隔を空ける。手動のストアリンクは引き続きいつでも使える。

## 検証と制約

レビュー固有15件＋記録/場所登録の回帰9件、計24テスト成功。別日・24時間・重複編集・アカウント分離・90日・同一バージョン・年3回・時計巻き戻り・履歴破損・静かな完了・タッチ・ダイアログ・保存中・背景復帰・アカウント変更・API利用不可・手動レビューとの競合・同時完了・API失敗を確認。静的解析エラー0、既存の警告/情報あり。iOS Simulator arm64のネイティブビルド成功。Flutter CLIでの全Simulator構成は既存SDKのarchitecture判定で失敗したため、Xcodeで単一構成を検証した。

iOSはin_app_review 2.0.12（StoreKit）、AndroidはGoogle Play In-App Reviewを使用。TestFlightではOSレビュー要求が表示されない。ローカルデバッグでは自動要求を無効とし、UIテストでは注入したAPIで制御を検証する。本番でも表示はOS判断であり、アプリから強制できない。表示されない場合に別ダイアログやストア起動へ自動フォールバックしない。

今回は配信済み198のソースから、この変更のみを別PRにした。通知・新ホーム案内・他の保留機能を含めず、アプリ配布は未実施。

# アプリ内フィードバック

マイページ左上の星 → フィードバックを送る、から入力フォームを開く。

- ユーザーIDは小さな固定表示。ログイン中はFirebase UID、未ログイン時は端末内に保存したゲストUUID。
- 内容は必須、最大2000文字。ヒントは「アプリの改善点や不具合などを教えてください！」。
- 「送信する」で `POST /api/app-feedback` を呼び、サーバーがSlackの受け付けを確認してから完了表示する。失敗時は内容を保持。
- 受付IDは同じ内容の再試行で維持し、内容を変更すると更新する。
- 下部の「※お問い合わせの場合はこちらまで」の「こちら」は既存の外部コンタクトフォームを開く。

## サーバー

- 本番反映済み: フィードバックAPIは `525d39f` で導入。現在の本番は楽天画像保存を含む `39ac66c`。自動配信チェック通過、稼働コードとヘルスチェックを確認。
- 専用の `SAKE_FEEDBACK_SLACK_WEBHOOK_URL` があれば使用し、未設定なら既存の `SLACK_WEBHOOK_URL` を使用する。秘密値はアプリへ含めない。
- 通知: ユーザーID、内容、版番号・ビルド番号、OS、受付ID。本文はSlackのplain_textで送る。
- 受信したユーザーIDは検証済み認証トークンと照合。ゲストは別のIDとして扱う。
- 連打・再試行は稼働プロセス内で10分間重複抑止。プロセス再起動をまたぐ重複抑止ではない。
- 通知失敗を成功扱いにせず503を返す。内容は専用DBには保存しない。
- 送信制限はユーザーIDごと10件／時、接続元ごと30件／時。

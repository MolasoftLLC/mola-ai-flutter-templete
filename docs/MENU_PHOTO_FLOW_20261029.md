# メニュー解析：撮影 → 確認して解析

2026-10-29。対象デザインは [Figma 73:694](https://www.figma.com/design/I7luppl852rXk9uNAnutoB?node-id=73-694) の「メニュー解析｜2ステップ UI」。既存のFlutterアプリに実装。

## 動作

- メニュー解析の入口を黄色の撮影ボタン、写真選択、直近2件の履歴に変更。「もっと見る」で既存の履歴一覧、各行からその履歴を開く。店舗・日付・件数・写真は実データ。
- 撮影・写真選択後は写真全体を確認する。スキャン画面のメニュー撮影からも同じ確認へ進み、自動解析や強制的な切り抜きを行わない。
- 写真はcontainで全体表示。タップで拡大・ピンチ操作。「撮り直す」「切り抜き」「この写真で解析する」を配置。
- 切り抜きは任意。四隅で範囲を調整し、表示中の向きに合わせた座標で別ファイルに保存。元写真は上書きしない。キャンセルは確認に戻り、「元に戻す」で原本を再選択できる。
- 解析中は対象写真と不定進捗、解析中止を表示。中止・通信失敗後は写真を保持して確認画面から再試行できる。
- 中止した解析や広告の遅延コールバックが次の解析を上書きしない。解析ごとに既存APIリポジトリのセッションを分離。開始ボタン連打による二重送信を防止。
- 既存のログイン・AI送信同意・好み設定・広告・利用上限・解析結果のマスター照合・履歴保存・店舗登録・保存/お気に入り処理を継続利用。マスター照合後は既存の結果表示へ戻り、詳細補完を継続する。
- 中止はクライアントの結果採用・画面更新を止める。送信済みのサーバー処理の取り消しや利用回数の返却を保証する機能は追加していない。
- 日本語・英語に対応。既存の下部ナビゲーションは再利用し、デザイン見本のダミー記号には置き換えていない。

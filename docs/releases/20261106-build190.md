# 5.0.54 (190) — 連続文字スキャンでお酒えらび

189は写真撮影→切り抜き→既存AIメニュー解析を呼んでおり、要求された連続OCRとは異なっていた。解析メニューの「お酒えらび」からカメラ映像の文字を端末内で読み、既存マスター候補を選んで連続追加する処理へ置き換えた。

- iOSはVision、Androidは同梱したML Kit日本語モデル。静止画撮影を呼ばず、カメラの音声を無効化。サーバーへ送るのは検索用の文字と味わい取得用のマスターIDだけ。
- 約450ms間隔、同じ読み取りが2回続いたら検索。1フレームずつ処理し、同じ検索はセッション内キャッシュを利用。古い検索応答は次の商品へ混ぜない。
- 既存GET /api/sakes/searchのみで最大4検索を並行。先に返った候補から表示し、応答順にかかわらず名称・分類を含む検索結果を銘柄だけの候補より先に置く。候補は既存の正のマスターIDのみ。
- OCRが空白を省いた「阿櫻特別純米」のような名称は、全名称と銘柄の両方で検索。価格・容量を検索から除くが2024などの年度は維持。該当商品がない場合も同銘柄マスターを選べる。
- 候補をタップするとチェックとカート件数が更新され、同じ画面で次の商品を読める。重複・20件上限を維持。写真から追加も端末内OCRに統一し、AI生成や画像送信は行わない。
- 味わい取得を候補表示や次の商品追加の待ち条件にしない。後から届いたプロフィールの保存と次の選択を直列化し、カートを上書きしない。味わい・好みが不足したときはマッチ率を捏造しない。
- 既存のカート・サンプル・好み条件・比較・詳細遷移を保持。
